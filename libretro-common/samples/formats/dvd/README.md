# Native DVD packet views

`rdvd_packet_read` consumes private-stream PES payloads from `rmpeg1_ps_next`.
It returns borrowed elementary payload spans, substream IDs, DVD audio header
metadata, and DVD-Video LPCM configuration. `rdvd_nav_read` reads the general
information of complete PCI/DSI records using explicit big-endian loads.

`rdvd_highlight_read` exposes PCI highlight timing, update modes, display
groups and bounded button counts. `rdvd_button_read` returns validated
rectangles/neighbors and a borrowed eight-byte command; the colour reader
unpacks IFO/PGC palette indices and 4-bit alpha. No palette or command is
interpreted as RGB or executed. Group indices are zero-based, button numbers
one-based and group-local; the wire button offset remains separate.

`rdvd_button_neighbor` validates a directional target, retaining the current
button for a zero neighbor. `rdvd_button_find` uses inclusive DVD-image
rectangles and chooses the lowest-numbered hit. Neither changes selection
state or triggers auto-action. Frontends must map viewport coordinates and
provide timing, inherited highlight-state merging, UOP/VM rules and SPU
rendering. These are bounded stateless readers, not a navigation session.

No FFmpeg, libdvdread or libdvdnav headers or libraries are used. The test's
optional VOB fixture is generated by an external FFmpeg executable; it is not
an application dependency.

`rdvd_spu_stream_feed` assembles standard SPU units, borrowing complete input
and lazily allocating one reusable bounded buffer for fragments. Use one
assembler per selected substream and reset on seek or discontinuity. The
first-fragment PTS is retained; views expire with the next feed/reset/free.

The SPU control reader exposes timed commands 0..6 without changing display
state. Validate the complete sequence before applying it; regional colour
changes (command 7) report unsupported. `rdvd_spu_decode_row` writes indices
0..3 directly into caller storage with no allocation or RGB expansion. Keep
separate top/bottom field cursors and discard a row on decode failure.

`rdvd_pgc_read` validates supplied serialized IFO program-chain spans,
including non-overlapping tables and increasing program cell maps. Accessors
expose program ranges, bounded cell sectors/IDs, raw YCrCb palettes and
borrowed pre/post/cell commands. `rdvd_pgci_table_read`/`rdvd_pgci_entry_read`
bound selected chains using the nearest later record, supporting unsorted
entries and shared records. All data is borrowed; no I/O or allocation occurs.
The caller must retain immutable IFO storage. Angle selection, parental
policy and command execution are not inferred from these metadata readers.

These readers do not decode audio/video, open VMGI/VTSI files or route titles,
execute VM commands, render menus or decrypt discs. Audio access-unit pointers
retain their DVD wire value; consumers must interpret their origin before
using them as offsets. Borrowed spans expire with the originating PES input.
LPCM accepts DVD-Video's 48/96 kHz and 16/20/24-bit configurations; DVD-Audio
AOB formats are outside this API.

Run `make check SANITIZER=address,undefined` for exhaustive header/truncation
tests, whole/split/bytewise PES input, borrowed pointer identity, timestamp
damage recovery, NAV general fields and every split of a highlighted PCI PES.
`make CC=x86_64-w64-mingw32-gcc
EXE=.exe all` builds the same tests for Windows.

An optional generated DVD fixture must contain MPEG video, AC-3 and PCI/DSI:

```sh
ffmpeg -f lavfi -i color=size=720x576:rate=25 \
  -f lavfi -i sine=sample_rate=48000 -t 0.4 \
  -c:v mpeg2video -b:v 2000k -c:a ac3 -ac 2 -ar 48000 -f dvd fixture.vob
./rdvd_packet_test fixture.vob
```

Format references checked for this implementation:

- [ITU-T H.222.0, MPEG systems](https://www.itu.int/rec/T-REC-H.222.0-202308-S)
- [FFmpeg MPEG demux format handling](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/mpeg.c)
- [FFmpeg DVD LPCM header fields](https://github.com/FFmpeg/FFmpeg/blob/master/libavcodec/pcm-dvd.c)
- [Published NAV wire layouts](https://github.com/xbmc/libdvdread/blob/master/src/dvdread/nav_types.h)
- [Published IFO wire layouts](https://github.com/xbmc/libdvdread/blob/master/src/dvdread/ifo_types.h)

References describe wire fields; this implementation does not include or call
the referenced libraries.

IFO helpers now read borrowed VMGI/VTSI management prefixes, VMG title
metadata and optional first-play chains. VTS chapter lookup resolves PTT
pairs through PGCIT into program/cell ranges without copying input tables.
Title/chapter numbers are one-based. These readers do not open VIDEO_TS
files, open BUP files, choose angles, execute VM commands or render menus.
Borrowed PGCI_UT readers expose language codes, extensions, menu flags and
bounded nested PGCITs. Menu lookup takes an explicit language index and
finds the first entry PGC for the requested VMG title or VTS menu ID. It
applies no language fallback, parental policy or UOP policy. Shared and
unsorted offsets are supported; malformed selected chains fail closed.
Full management attributes remain unimplemented.

Source-routing helpers select a borrowed primary IFO or BUP management
prefix of an explicit VMG/VTS kind, find exact menu language/extension
matches, and generate validated VIDEO_TS basenames. Backup selection checks
management validity only; a corrupt nested table in a valid primary is not
automatically retried against BUP. Filesystem opening, case-insensitive
lookup, full-table validation and title-VOB concatenation remain caller work.

Title VOB geometry borrows 1..9 nonempty sector-aligned file sizes. Span
lookup splits logical byte requests at file boundaries without staging
payloads. Cell range lookup checks inclusive PGC sector bounds against the
whole title source using 64-bit arithmetic. Callers supply the matching VTS
title domain, own file handles and read each span into consumer storage.
Menu VOBs, angle/interleave policy and physical-disc routing are separate.

IFO table selection distinguishes menu/title C_ADT and VOBU_ADMAP domains.
Borrowed cell-address readers validate record IDs and inclusive bounds.
VOBU maps validate strict sector ordering; floor lookup returns the last
start at or before a target, including valid sector zero. Callers check
cell/domain and source geometry before I/O. Lookup revalidates the complete
map before its binary search; no latency or playable-seeking claim is made.

Title-target resolution combines chapter/program mapping, a selected cell,
a unique title C_ADT identity, cell-bounded VOBU lookup and VOB geometry.
It returns the NAV sector, logical bytes remaining in the cell and the
first file-local read span without staging data. The caller owns the VTS
source and must preserve that domain pairing. Angle/block and interleaved
cells are rejected until navigation policy exists. No time seek, file read,
VM execution or playable title/menu integration is implemented by this API.

The rdvd_source request/completion interface starts from a logical range
or checked title target and reserves one file-local read into consumer-owned
storage. The owning task dispatches I/O externally and reports completions
serially by ticket. Positive short reads preserve progress; errors retain
the completed prefix. Cancellation stops new requests and drains a pending
completion before storage can be reused. Initialization requires fresh or
drained state; map sizes and pending destinations must stay alive. No locks,
waits, file-opening or staging copies are added. A backend/task adapter and
player integration are still required.

Backend binding borrows segment handles and shares the source's immutable
size array. Submit/poll callbacks must return immediately and schedule I/O
externally; no synchronous filestream adapter is introduced. Dispatch uses
the correct segment handle and the original consumer destination. One source
may own a backend at a time. Poll consumes matching terminal tickets and
releases ownership; cancellation retains ownership until the read drains.
Concrete filesystem adapters, handle opening/closing and player task wiring
remain to be implemented. Backend callbacks must not reenter source calls.
