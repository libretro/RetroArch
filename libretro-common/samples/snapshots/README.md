# Runtime snapshot test host

RetroArch owns this standalone public-libretro test consumer.
It has no RetroArch headers or core-private dependencies. Cores keep their
profiles and workload generators in their own test directories. Cores fetch a pinned copy for
testing instead of maintaining their own copies of the host and runners.

Build with `make` and a desktop C compiler. Linux links libdl; native Windows
uses MinGW and LoadLibrary. No build output belongs in source control.
Explicit builds recompile the host/proxy; `make check` covers revision switching,
failed-build retry and source fetching.

`snapshot_smoke CORE NEW_DIRECTORY PROFILE CONTENT [SYSTEM_DIRECTORY]` checks
retained guest GPU/RSP reads, full RAM, normalized software RGB, repeated loads
and independent ownership. Profiles are unquoted key=value lines. @rsp and
@presented enable the original N64 workload and borrowed-frame checks.
The original PS-X workload is generated by `snapshot_smoke --generate-psx DIR`.
Both workloads read changing retained state before replacing it.

Hardware rendering is a separate optional test through the frontend proxy.
It requires an independently built RetroArch with desktop GL/Vulkan and normal
screenshot support; no path to a different core repository is required.
The software host deliberately rejects hardware callbacks.

These tests are finite continuation checks, not universal accuracy or speed
certification. Core-specific omissions must be detected by their actual guest
consumer or an image comparison; a nonzero exit by itself is insufficient.

Build the optional proxy with `make gpu`. Run hardware profiles with:

```sh
python3 run_gpu_profiles.py --frontend /path/to/retroarch \
  --proxy build/snapshot_proxy.so --core /path/to/core.so \
  --content /path/to/fixture --suite /path/to/gpu-suite.json \
  --output /new/writable/directory
```

Each hardware profile runs an uninterrupted reference and a restored
continuation with the same driver/options. The proxy checks guest reads and
full RAM while the real frontend owns the GPU context and presentation. The
runner compares final screenshots as decoded RGB, requires nonblank images,
and records hashes, dimensions and pixel differences. The comparison is exact
within one driver/configuration, not between different renderers.

This proxy schedules snapshots itself. It does not exercise RetroArch's
run-ahead/preemptive scheduler, device loss or allocation failures. Frontend
integration and core-specific transitions need separate tests. There is no
performance measurement here.

`@frontend=ordinary` accepts registration without activating snapshots;
`@frontend=decline` rejects it, including an older interface version.
`@ordinary_load=1` checks rejected ordinary loads, subsequent progress, a
copied ordinary state and successful-load invalidation. Use these only when
the profile's core supports the tested ordinary-state behavior. `equal_to`
compares a profile's final RAM/RGB with an earlier profile; `counter_delta`
checks an expected guest-frame difference. An optional `--system` supplies
read-only firmware without putting firmware in the test repository.

## Pinned test dependency

A core keeps `fetch_harness.py` and `harness.lock.json` in its test directory.
The lock names a full RetroArch commit and SHA-256 for each needed file,
including `libretro-common/include/libretro.h`. Only explicit test targets
fetch sources. Normal core builds and gameplay have no network dependency.

`fetch_harness.py --path` prints the cache path without fetching. A normal
invocation checks the cache and fetches missing files; `--offline` requires
a complete cache. `--cache DIRECTORY` selects another cache. Checksums are
checked before use, and interrupted or mismatched downloads are not published.
Cores expose `TOOLS` to use this directory from a local RetroArch checkout,
bypassing the pin and all downloads for development or offline tests.

The small fetch helper is copied into core test directories; the host, proxy,
profile runners and their checks remain here. When updating the helper, run
`python3 test_fetch_harness.py`. Update a core's lock only after publishing the
chosen revision and calculating checksums from its Git blobs (not a working
tree with converted line endings). Do not follow a branch head or tag.
